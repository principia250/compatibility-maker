# データベース詳細設計書

## 1. データベース概要

### 1.1 データベースエンジン

- **エンジン**: PostgreSQL 15
- **ホスティング**: Supabase
- **バックアップ**: 自動（日次）
- **リージョン**: 東京リージョン（推奨）

### 1.2 設計方針

- 正規化されたテーブル構造
- 適切なインデックス戦略
- Row Level Security (RLS) によるセキュリティ
- パフォーマンスを考慮したクエリ最適化

## 2. テーブル定義

### 2.1 ユーザーテーブル (users)

```sql
CREATE TABLE users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  auth_user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  username TEXT UNIQUE NOT NULL,
  plan_type TEXT NOT NULL DEFAULT 'free' CHECK (plan_type IN ('free', 'supporter', 'premium')),
  plan_expires_at TIMESTAMP WITH TIME ZONE,
  plan_updated_at TIMESTAMP WITH TIME ZONE,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- インデックス
CREATE INDEX idx_users_auth_user_id ON users(auth_user_id);
CREATE INDEX idx_users_username ON users(username);
CREATE INDEX idx_users_plan_type ON users(plan_type);
CREATE INDEX idx_users_plan_expires_at ON users(plan_expires_at);

-- トリガー: updated_at自動更新
CREATE OR REPLACE FUNCTION update_updated_at_column()
RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at = NOW();
  RETURN NEW;
END;
$$ language 'plpgsql';

CREATE TRIGGER update_users_updated_at
  BEFORE UPDATE ON users
  FOR EACH ROW
  EXECUTE FUNCTION update_updated_at_column();
```

## 3. ER図 (Entity Relationship Diagram)

```
users (1) ←→ (N) compatibility_charts
                ↓
            (1) ←→ (N) elements
                ↓
            (N) ←→ (N) compatibilities ←→ (1) compatibility_scores
                ↓
            (1) ←→ (N) comments
                ↓
            (1) ←→ (N) goods
                ↓
            (1) ←→ (N) bookmarks
```

### 3.1 リレーション詳細

- **users → compatibility_charts**: 1対多（1人のユーザーが複数の相性図を作成）
- **compatibility_charts → elements**: 1対多（1つの相性図に複数の要素）
- **elements → compatibilities**: 多対多（要素間の相性関係）
- **compatibilities → compatibility_scores**: 多対1（相性関係とスコアの対応）
- **compatibility_charts → comments**: 1対多（1つの相性図に複数のコメント）
- **compatibility_charts → goods**: 1対多（1つの相性図に複数のGood）
- **compatibility_charts → bookmarks**: 1対多（1つの相性図を複数のユーザーがブックマーク）

## 4. Row Level Security (RLS) 設定

### 4.1 ユーザーテーブル

```sql
-- RLS有効化
ALTER TABLE users ENABLE ROW LEVEL SECURITY;

-- ポリシー: ユーザーは自分のデータのみアクセス可能
CREATE POLICY "Users can view own profile" ON users
  FOR SELECT USING (auth.uid() = auth_user_id);

CREATE POLICY "Users can update own profile" ON users
  FOR UPDATE USING (auth.uid() = auth_user_id);
```

### 4.2 相性図テーブル

```sql
-- RLS有効化
ALTER TABLE compatibility_charts ENABLE ROW LEVEL SECURITY;

-- ポリシー: 公開された相性図は誰でも閲覧可能
CREATE POLICY "Public charts are viewable by everyone" ON compatibility_charts
  FOR SELECT USING (is_public = true);

-- ポリシー: 作成者は自分の相性図を編集・削除可能
CREATE POLICY "Users can view own charts" ON compatibility_charts
  FOR SELECT USING (auth.uid() = user_id);

CREATE POLICY "Users can insert own charts" ON compatibility_charts
  FOR INSERT WITH CHECK (auth.uid() = user_id);

CREATE POLICY "Users can update own charts" ON compatibility_charts
  FOR UPDATE USING (auth.uid() = user_id);

CREATE POLICY "Users can delete own charts" ON compatibility_charts
  FOR DELETE USING (auth.uid() = user_id);
```

### 4.3 要素テーブル

```sql
-- RLS有効化
ALTER TABLE elements ENABLE ROW LEVEL SECURITY;

-- ポリシー: 相性図の作成者のみ要素を管理可能
CREATE POLICY "Elements are viewable with chart access" ON elements
  FOR SELECT USING (
    EXISTS (
      SELECT 1 FROM compatibility_charts
      WHERE id = chart_id
      AND (is_public = true OR auth.uid() = user_id)
    )
  );

CREATE POLICY "Users can manage elements in own charts" ON elements
  FOR ALL USING (
    EXISTS (
      SELECT 1 FROM compatibility_charts
      WHERE id = chart_id
      AND auth.uid() = user_id
    )
  );
```

### 4.4 相性テーブル

```sql
-- RLS有効化
ALTER TABLE compatibilities ENABLE ROW LEVEL SECURITY;

-- ポリシー: 相性図の作成者のみ相性を管理可能
CREATE POLICY "Compatibilities are viewable with chart access" ON compatibilities
  FOR SELECT USING (
    EXISTS (
      SELECT 1 FROM compatibility_charts
      WHERE id = (
        SELECT chart_id FROM elements WHERE id = left_element_id
      )
      AND (is_public = true OR auth.uid() = user_id)
    )
  );

CREATE POLICY "Users can manage compatibilities in own charts" ON compatibilities
  FOR ALL USING (
    EXISTS (
      SELECT 1 FROM compatibility_charts
      WHERE id = (
        SELECT chart_id FROM elements WHERE id = left_element_id
      )
      AND auth.uid() = user_id
    )
  );
```

### 4.5 コメントテーブル

```sql
-- RLS有効化
ALTER TABLE comments ENABLE ROW LEVEL SECURITY;

-- ポリシー: 公開された相性図のコメントは誰でも閲覧可能
CREATE POLICY "Comments are viewable with chart access" ON comments
  FOR SELECT USING (
    EXISTS (
      SELECT 1 FROM compatibility_charts
      WHERE id = chart_id
      AND (is_public = true OR auth.uid() = user_id)
    )
  );

-- ポリシー: ログインユーザーのみコメント投稿可能
CREATE POLICY "Authenticated users can insert comments on public charts" ON comments
  FOR INSERT WITH CHECK (
    auth.uid() IS NOT NULL
    AND EXISTS (
      SELECT 1 FROM compatibility_charts
      WHERE id = chart_id
      AND is_public = true
    )
  );

-- ポリシー: コメント投稿者は自分のコメントを編集・削除可能
CREATE POLICY "Users can update own comments" ON comments
  FOR UPDATE USING (auth.uid() = user_id);

CREATE POLICY "Users can delete own comments" ON comments
  FOR DELETE USING (auth.uid() = user_id);
```

### 4.6 Good・ブックマークテーブル

## 6. パフォーマンス最適化

### 6.1 インデックス戦略

- **プライマリキー**: 自動的にクラスタ化インデックス
- **外部キー**: 結合クエリの高速化
- **検索用インデックス**: タイトル検索の高速化（全文検索）
- **ソート用インデックス**: 作成日時、Good数でのソート高速化

### 6.2 クエリ最適化

```sql
-- 相性図一覧取得（公開済み）
SELECT
  c.id,
  c.title,
  c.left_category,
  c.right_category,
  c.created_at,
  u.username as creator_name,
  COUNT(g.id) as good_count,
  COUNT(b.id) as bookmark_count
FROM compatibility_charts c
JOIN users u ON c.user_id = u.id
LEFT JOIN goods g ON c.id = g.chart_id
LEFT JOIN bookmarks b ON c.id = b.chart_id
WHERE c.is_public = true
GROUP BY c.id, c.title, c.left_category, c.right_category, c.created_at, u.username
ORDER BY c.created_at DESC;

-- 相性図詳細取得（要素と相性）
SELECT
  e.id,
  e.name,
  e.position,
  e.category,
FROM elements e
WHERE e.chart_id = $1
ORDER BY e.position;

-- 相性データ取得
SELECT
  cs.score as compatibility_score,
  cs.label as score_label,
  c.notes,
  left_e.name as left_element,
  right_e.name as right_element
FROM compatibilities c
JOIN elements left_e ON c.left_element_id = left_e.id
JOIN elements right_e ON c.right_element_id = right_e.id
JOIN compatibility_scores cs ON c.compatibility_score_id = cs.id
WHERE left_e.chart_id = $1;
```

## 7. データ整合性制約

### 7.1 チェック制約

- 相性スコア: compatibility_scoresテーブルで管理（-2 から 2 の範囲）
- プランタイプ: 'free', 'supporter', 'premium' のみ
- 要素位置: 同一チャート内で一意

### 7.2 外部キー制約

- カスケード削除: 相性図削除時に関連データも削除
- 参照整合性: 存在しないIDへの参照を防止

### 7.3 トリガー

- updated_at自動更新: データ更新時のタイムスタンプ自動更新
